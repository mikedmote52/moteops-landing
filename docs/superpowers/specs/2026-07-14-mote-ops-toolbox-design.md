# Mote Ops Toolbox Homepage Section Design

Date: 2026-07-14

## Objective

Add a compact homepage section that proves Mote Ops can work across current automation, AI, integration, and delivery tools without making the website feel like a technology catalog. The section must strengthen credibility while keeping the customer problem and business outcome primary.

## Audience

The primary reader is a small business owner with limited technical knowledge. The reader may recognize names such as n8n, OpenAI, or Claude, but should not need to understand those products to understand the offer.

## Positioning Principle

Mote Ops is the integration partner. The technology is the toolbox, not the product. The section must communicate three ideas:

1. Mote Ops can select from modern tools.
2. The client does not need to choose or learn the stack.
3. The system is built around the client's existing workflow and supported after launch.

The section must not imply that every named tool is deployed in every project. It must distinguish available build tools from the separately verified technical evidence on Mike's Mac.

## Placement

Place the section after the working demonstrations and case story, and before the collapsed technical proof disclosure. This order preserves the homepage narrative:

1. Recognize the business problem.
2. Understand the Mote Ops service.
3. See working examples.
4. See the available toolbox.
5. Inspect technical proof if desired.

## Content

Eyebrow:

`THE MOTE OPS TOOLBOX`

Heading:

`Built with the right tools. Never trapped in one.`

Introduction:

`Mote Ops selects, connects, and supports the technology that fits your business. You do not need to learn the platforms or decide which model to use.`

The toolbox is organized by customer purpose rather than vendor category.

### Automate

Tools and methods: n8n, webhooks, scheduled workflows, APIs.

Customer meaning: repetitive work can move reliably between systems.

### Think

Tools and methods: OpenAI, Claude, Codex, Ollama, private local models.

Customer meaning: the appropriate model is selected for the task, privacy needs, and budget.

### Connect

Tools and systems: Gmail, Microsoft 365, calendars, forms, customer software.

Customer meaning: Mote Ops works around the software the business already uses where practical.

### Deliver

Outputs: custom dashboards, approval queues, phone access, operating briefs.

Customer meaning: useful work appears in a clear interface where a person can review and act.

Closing statement:

`Technology changes quickly. Your system should keep working. Mote Ops chooses the tools, connects them to your real workflow, tests the result, and helps your team use it.`

## Visual Treatment

Use the existing cream, dark green, orange, and black visual system. Do not add blue. Do not use a conventional logo cloud.

Present the four purposes as a structured editorial toolbox. Each group receives a short uppercase label, one plain language explanation, and a restrained line of tool names. The visual should feel like a field guide or workshop inventory rather than a software marketplace.

On wide screens, show the four groups in one balanced row or a two by two arrangement if the available width makes the names easier to read. On mobile, stack the groups in a single column with no horizontal scrolling.

## Interaction

The section is informational and contains no controls. No tool name should behave like a link unless it leads to a real Mote Ops demonstration or an intentionally maintained explanatory page. This avoids decorative interactions that do nothing useful.

## Accessibility

Use semantic headings and list structure. Preserve readable contrast. Tool names must remain text rather than being embedded in images. The section must be understandable without color and must not introduce motion.

## Truth Boundaries

1. The section describes the toolbox Mote Ops can use, not a promise that every tool appears in every client installation.
2. The section must not say that n8n is part of the current verified Mac installation unless separate evidence supports that claim.
3. The existing technical proof disclosure remains the source for claims about what is currently verified on Mike's Mac.
4. Microsoft 365 and other client systems must be described as connectable or selectable tools, not completed live client integrations unless verified.
5. Outcomes remain subject to discovery, permissions, testing, and client configuration.

## Verification

Automated checks should confirm:

1. The section includes n8n, OpenAI, Claude, Codex, Ollama, Gmail, and Microsoft 365.
2. The section includes the four purpose labels Automate, Think, Connect, and Deliver.
3. The section appears after the demonstration and case story content and before the technical proof disclosure.
4. The page does not introduce blue styling or horizontal overflow at 390 pixels.
5. Existing demonstration behavior, email choices, navigation, and booking links remain functional.

Manual review should confirm that a nontechnical owner can understand why the tools are shown without knowing what each tool does.
